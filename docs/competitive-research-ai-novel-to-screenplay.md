# AI 小说转剧本工具竞品调研

调研日期：2026-06-06  
调研对象：面向小说、故事文本、短剧/漫剧创作者的 AI 改编、剧本生成、分镜生成与成片工具。

## 1. 结论摘要

AI 小说转剧本工具正在分成三类路线：

1. **中文短剧/漫剧流水线工具**：从小说或故事输入，输出分集剧本、分镜、角色/场景资产，甚至直接合成短剧视频。代表产品包括知剧 AI、奇漫 AI、海豹分镜、剧火 AI、辰入梦、VIVAShort、趣写、ArcReel。
2. **海外专业编剧/长篇写作工具**：强调故事记忆、结构化 Story Bible、标准剧本格式、FDX/PDF 导出和协作。代表产品包括 Scriptyn、AnyStory、ThinkBookAI、Sudowrite、Plotdot、Final Draft。
3. **开源/可部署生产线**：以 ArcReel 为代表，核心卖点是数据自持、模型供应商可切换、长篇小说可拆分处理，适合技术团队或工作室内部流程。

当前市场的共同痛点不是“能不能生成剧本”，而是：

- 长篇小说上下文过长，角色、伏笔、设定容易丢失。
- 小说语言到视听语言的转换质量不稳定，常把心理描写、旁白、解释性文字硬塞进台词。
- 短剧/漫剧平台强调快速出片，但编剧可控性、版本追踪、审稿协作仍偏弱。
- 专业编剧工具格式成熟，但对中文网文、短剧节奏、爽点拆分、平台化生产的适配不足。

因此，一个新的 ScriptForge 类产品若要切入，建议主打：**长篇小说理解 + 可控改编工作台 + 中文短剧/影视剧本格式 + 版本化审稿 + 可导出生产交付物**，避免只做“一键生成剧本”的薄功能。

## 3. 国内竞品观察

### 3.1 中文短剧工具的主链路趋同

国内产品普遍围绕“小说/故事/剧本 -> 分集台本 -> 分镜 -> 角色/场景资产 -> 视频/导出”展开。知剧 AI 明确提供“小说转剧本”模式，上传小说后做章节分析、情节提取、对白改编；奇漫 AI 更强调漫画分镜剧本和多语言翻译；海豹分镜则把小说片段或故事梗概转为带对白、场景标注、人物情绪的短剧剧本，并继续生成分镜和统筹表。

这说明市场已经教育用户接受“小说转短剧/漫剧”的概念。新产品如果只说“AI 改编”，表达会显得泛；更好的表述是把交付物说清楚：分集大纲、场次表、人物表、场景表、对白稿、分镜脚本、FDX/PDF/DOCX/XLSX。

### 3.2 “一键成片”正在抢占短剧创作者

剧火 AI、辰入梦、VIVAShort 等工具都在把剧本能力前置为视频生产链路的一环。它们的优势是结果感强，用户能从一个故事直接看到画面、配音和短剧成片。

但这类工具通常会面临两个问题：

- 对真正有 IP 改编需求的团队来说，剧本阶段需要大量审稿、拆改、合规、节奏调整，不适合完全黑箱生成。
- 视频生产工具的能力重心会分散到模型、素材、时间线、画质、音频，剧本本身可能只是流水线中间件。

ScriptForge 可以避开与“一键成片”正面硬拼，把自己定位为上游“IP 改编与剧本开发中枢”，然后导出到分镜/视频工具。

### 3.3 数据安全和长篇处理开始成为卖点

ArcReel 明确强调 AGPL-3.0 开源、可自部署、数据不出本机、模型 API Key 自持，并通过多 Agent 处理长篇小说上下文。这对网文 IP、影视公司、工作室尤其重要，因为原著内容、改编方案和角色资产具有商业敏感性。

这给 ScriptForge 的启发是：即使先做 SaaS，也应在产品层面预留“项目私有化、模型供应商切换、内容不训练、导出全量项目包”等信任机制。

## 4. 海外竞品观察

### 4.1 海外更强调专业写作环境和格式标准

Scriptyn 的卖点是 AI 结构、连续性、格式化、PDF/FDX/纯文本导出；Final Draft 作为行业标准软件，强调自动格式化、规划、协作、生产报告和行业接受度。这类产品的核心不是“生成一段剧本”，而是让编剧在专业环境中持续工作。

对 ScriptForge 来说，中文短剧格式之外，还应该支持更专业的输出层：

- 标准 screenplay / teleplay / stage play 格式。
- FDX、PDF、DOCX、Markdown、CSV/XLSX 场次表。
- 角色、场景、道具、时间线、场次统计。
- 与 Final Draft、WriterDuet、剪辑/分镜工具之间的导入导出。

### 4.2 长篇记忆是小说改编的底层能力

AnyStory、ThinkBookAI、Sudowrite 都把“项目上下文”“Story Bible”“角色状态”“世界规则”“修订历史”放在核心位置。ThinkBookAI 甚至提出 Master Format，并在 Novel View 与 Script View 之间切换。

小说转剧本不是单次 Prompt，而是一个结构化数据转换问题：原文、人物、事件、关系、地点、时间线、伏笔、爽点、章节节奏都需要抽取、确认、再映射到剧本结构。

## 5. 机会点

### 5.1 做“可审稿”的小说改编，而不是“一键出稿”

竞品普遍强调生成速度，但 IP 改编的真实流程更像：

1. 解析原著：角色、关系、场景、事件、时间线、伏笔、冲突。
2. 生成改编策略：保留/删减/合并角色，章节到集数映射，爽点和钩子布局。
3. 人工确认：断点、主线、副线、人物设定、尺度和平台要求。
4. 生成剧本：分集大纲、场次表、台词、动作、场景描述。
5. 审稿改写：按人物、节奏、成本、合规、平台风格迭代。
6. 交付导出：制片表、分镜输入、FDX/PDF/DOCX/XLSX。

如果产品把每一步都做成可编辑、可回退、可对比的节点，就会比普通生成器更适合团队生产。

### 5.2 中文网文/短剧节奏是本地化壁垒

中文网文改短剧有非常具体的节奏：强钩子、短场景、密集反转、人设标签、情绪价值、平台审美、单集时长限制。海外编剧工具不擅长这部分，国内视频工具又未必有专业剧本管理深度。

可沉淀为产品模板：

- 男频逆袭、女频甜宠、古风权谋、悬疑反转、都市情感、霸总、复仇、赘婿等题材模板。
- 1 分钟、2 分钟、5 分钟、10 分钟单集结构。
- 每集结尾钩子强度评分。
- 爽点/泪点/笑点/反转点标注。
- 原著章节到短剧集数映射表。

### 5.3 “故事资产层”比编辑器更重要

从竞品看，角色库、场景库、知识库、Story Bible 是关键能力。ScriptForge 应将小说改编后的核心信息沉淀为结构化故事资产：

- 人物：身份、动机、关系、口癖、成长线、出场集数。
- 场景：地点、时代、成本等级、可复用性。
- 事件：章节来源、冲突、结果、影响人物。
- 台词：人物语气、信息量、潜台词、可替代表达。
- 制作约束：预算、演员数量、场景数量、平台尺度。

这样每次生成不是从空白开始，而是围绕项目资产做检索和改写。

## 6. 建议的产品定位

建议定位为：

> 面向中文网文 IP、短剧团队和编剧工作室的 AI 小说改编工作台，把长篇小说拆解为可审稿、可协作、可交付的专业剧本与生产资料。

不建议定位为：

- “一键 AI 写剧本”：太泛，易被通用大模型和轻量工具替代。
- “AI 一键成片”：会直接卷入视频模型、素材一致性、剪辑合成的重资产竞争。
- “纯剧本编辑器”：难以区别于 Final Draft、剧云等专业工具。

更合适的差异化表达：

- 长篇小说读得懂：支持大体量原文分段解析和角色/情节一致性维护。
- 改编过程看得见：章节到剧集、事件到场次、人物到台词均可追踪。
- 编剧团队改得动：每集、每场、每条台词可批注、重写、对比版本。
- 交付物拿得走：剧本、分镜输入、统筹表、角色表、场景表、多格式导出。

## 7. MVP 功能建议

### 7.1 第一阶段：小说解析与改编规划

- 上传 TXT/MD/DOCX 小说。
- 自动拆章并生成章节摘要。
- 抽取人物、关系、场景、关键事件。
- 生成“原著章节 -> 剧集/场次”映射。
- 支持用户确认或调整分集断点。

### 7.2 第二阶段：短剧剧本生成

- 按题材模板生成分集大纲。
- 按单集时长生成场次表。
- 生成标准台本：场景、动作、对白、情绪、镜头提示。
- 支持“保留原著对白/强化短剧冲突/降低制作成本”等改写模式。

### 7.3 第三阶段：审稿与导出

- 版本对比与回退。
- 人物一致性检查：称谓、关系、动机、口吻。
- 节奏检查：每集钩子、高潮、信息密度。
- 导出 MD/DOCX/PDF/XLSX，后续支持 FDX。

## 8. 风险与待验证问题

- **版权与授权风险**：用户上传小说是否拥有改编权，需要产品协议、项目权限和水印/审计机制。
- **生成内容责任**：剧本可能涉及侵权、低俗、敏感或平台违规内容，需要合规检查。
- **长文本成本**：长篇小说解析需要分块、缓存、摘要层级和增量更新，否则成本不可控。
- **质量评估难**：改编质量不是单纯语法问题，需要建立剧情保真度、可拍性、节奏、人物一致性等指标。
- **工作流复杂度**：专业用户要可控，轻量用户要快，界面需要在“向导式”和“专业工作台”之间平衡。
